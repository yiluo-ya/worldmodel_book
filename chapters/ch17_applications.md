# 第 17 章　应用地图：世界模型在真实系统里长什么样

## 17.1 四个领域，四种形态

世界模型不是一个统一的技术，它在不同领域的形态差别很大：

| 领域 | 预测什么 | 典型时长 | 精度要求 | 代表工作 |
|---|---|---|---|---|
| 机器人控制 | 本体状态、接触 | 0.1-2 s | 高（毫米级） | Dreamer、TD-MPC、DayDreamer |
| 自动驾驶 | BEV 表征、他车轨迹 | 2-8 s | 中（米级）+ 保守 | GAIA-1、OccWorld、DriveDreamer |
| 游戏/交互内容 | 下一帧画面 | 秒-分钟 | 视觉一致即可 | Genie、GameNGen、Oasis |
| 科学/工程 | 物理场、分子构象 | 不定 | 极高 | 神经算子、AlphaFold 类 |

下面挑机器人和自动驾驶展开，因为它们的工程约束最硬。

## 17.2 机器人：三种落地形态

### (1) 模型预测控制（MPC）里的模型

- **要求**：快（毫秒级）、在短视界内准、可微（若用梯度规划）
- **形态**：小 MLP、二次模型、或白盒 + 学残差
- **本书对应**：ch8、ch13
- **注意**：视界很短（0.1-0.5 s），所以模型不需要"长期正确"

这是**最容易落地**的形态。很多工业 MPC 用的就是"线性化 + 在线辨识"，
本质上是一个每步更新的世界模型。

### (2) 策略学习的想象力（Dreamer 类）

- **要求**：latent 表征稳定、能在里面 rollout 15-50 步
- **形态**：RSSM / Transformer
- **本书对应**：ch9、ch15
- **注意**：一定要用真实数据校准价值函数，否则会在幻觉里越跑越偏

DayDreamer（Berkeley）是标志性工作：四足机器人在真实世界几小时内学会行走，
几乎不用仿真。核心就是"世界模型 + 想象 + 少量真机数据"。

### (3) 仿真器的加速器（神经代理模型）

- **要求**：比物理引擎快 100-1000 倍，精度可接受
- **形态**：图网络、神经算子
- **用法**：用于大规模策略搜索、参数扫掠
- **注意**：只在不关心的维度上允许误差（比如不关心视觉细节）

这类模型常见于工业：用 CFD 数据集训一个"一秒出结果"的代理模型，
替代原来要跑几小时的仿真。

## 17.3 自动驾驶：为什么用世界模型

自动驾驶的核心矛盾：**长尾场景极少见，但必须处理**。

- 真实路测一百万公里也遇不到几次"小孩追球跑出来"
- 仿真能造这些场景，但仿真器的保真度有限（传感器模型、行为模型）

世界模型在这里的三个用途：

1. **场景生成**（生成罕见的、逼真的危险场景）
2. **闭环仿真**（让被测系统在"学出来的世界"里跑）
3. **预测他车**（预测周围交通参与者未来 3-8 秒的轨迹）

第三条最成熟。它的关键技术问题：

- **多模态**：他车可能左转、直行、右转。单一预测会"平均"成一个撞车的轨迹
  （这是 ch4 §4.6 说的 MSE 均值问题）
- **交互**：多车互相影响，需要 joint prediction
- **不确定性**：必须给出分布，因为下游规划要"避开最坏情况"

所以自动驾驶的轨迹预测几乎都用**混合密度网络/扩散模型 + 大量数据**，
而不是单点回归。

## 17.4 游戏与视频生成：最"看起来像"的世界模型

Genie / GameNGen / Oasis 这类工作，输入是操作（键盘），输出是下一帧画面。
它们在**视觉上**非常震撼，但在**可控性**上远不如机器人世界模型：

| 维度 | 机器人世界模型 | 视频世界模型 |
|---|---|---|
| 目标 | 物理量正确 | 画面合理 |
| 评估 | 任务成功率 | 视觉质量 + 一致性 |
| 时间尺度 | 秒 | 分钟 |
| 交互 | 严格因果、实时 | 常离线、可能"编" |
| 失败模式 | 摔、撞 | 画面漂移、物体凭空消失 |

一个重要的提醒：**视频世界模型目前还不能可靠用于闭环控制**。
原因是它们不保证物理量一致（exp06 的排名颠倒就是微缩版）。

## 17.5 科学计算：最"准"的世界模型

这类工作不怎么叫"world model"，但本质一样：

- **神经算子**（FNO、DeepONet）：学"输入场 → 输出场"的映射
- **分子动力学代理**：学势能面，替代 DFT 计算
- **天气预报**（GraphCast、Pangu）：学大气演化

特点：

- 数据来自高保真仿真（"真值"便宜）
- 精度要求极高（不能有系统偏差）
- 结构化先验用得最多（对称性、守恒律、多尺度）

**这一块是最能体现 ch13（结构化先验）价值的地方。** 纯黑箱在科学领域
几乎不可能通过验收，因为外推（新工况）太频繁。

## 17.6 一个跨领域的共性结论

把四个领域放在一起，能看到三条通用规律：

### (1) 越"物理"的领域，结构化先验越重要

机器人/科学：白盒 + 学习残差是主流。
游戏/内容：纯黑箱。

### (2) 越安全关键的领域，不确定性越重要

自动驾驶必须有分布外检测；机器人力控必须有力/位混合的安全边界。
视频生成不需要。

### (3) 越需要长时程，越需要"模型 + 价值函数"

短视界（<1 s）：纯模型 + 规划就够（ch8）。
长视界（>5 s）：必须有价值函数/终端代价来"替代"远期预测（ch16 §16.3）。

## 17.7 一个可以抄的系统架构

如果你要在一个真实机器人上做世界模型，推荐这个分层结构：

```
┌──────────────────────────────────────────┐
│ 任务层：规划 / 状态机 / LLM 任务理解        │  ~1 Hz
├──────────────────────────────────────────┤
│ 策略层：学习策略 或 MPC（用世界模型）        │  ~10-100 Hz
├──────────────────────────────────────────┤
│ 世界模型：预测未来 0.1-0.5 s                │  每控制周期
│   - 白盒物理 + 学习残差                     │
│   - 集成（3-5 个）用于不确定性               │
├──────────────────────────────────────────┤
│ 状态估计：EKF / 视觉里程计 / 学习估计器      │  ~200-1000 Hz
├──────────────────────────────────────────┤
│ 硬件层：PD 力矩控制                        │  ~1000 Hz
└──────────────────────────────────────────┘
```

三个要点：

1. **世界模型不在最底层**。底层的 1 kHz 力矩控制不能让神经网络来做
   （延迟、稳定性都没保证）。世界模型服务于 10-100 Hz 的决策层。
2. **每层有独立的 fallback**。模型不可信 → 退回 PD；状态估计失效 → 停机。
3. **不确定性从下往上传播**。底层的估计噪声影响世界模型，世界模型的
   不确定度影响规划。这条链要有明确的接口。
