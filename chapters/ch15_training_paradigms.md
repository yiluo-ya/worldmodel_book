# 第 15 章　训练范式：怎么把零件组装成系统

## 15.1 三种组装方式

世界模型不是单独存在的，它总是嵌在某个更大的循环里。三种典型结构：

### (1) 离线监督（本书大部分）

```
采数据（固定） → 训模型（固定） → 用（不再更新）
```
优点：简单、可复现。缺点：模型不知道自己要用来做什么。

### (2) Dyna 循环（在线/半在线）

```
采一点 → 训一点 → 用一点 → 失败的数据回流 → 再训
```
优点：数据效率高，能自适应。缺点：工程复杂（要处理非稳态、灾难遗忘）。

### (3) 联合训练（端到端）

```
把模型、编码器、策略、价值函数、奖励函数全塞进一个损失一起优化
```
优点：表征会自动保留"有用"的信息。缺点：训练不稳定，调参地狱。

现代系统基本是 (2) 和 (3) 的混合：**模型用大量离线数据预训练，
然后在 Dyna 循环里微调**。

## 15.2 Dreamer 的配方（值得完整理解）

Dreamer 是目前最成功的一套"世界模型 + 策略"范式。它的循环：

```
① 用真实数据训 latent 世界模型（RSSM）
       ↓
② 从真实状态出发，在 latent 空间里"想象" H 步（H = 15-50）
       ↓
③ 用想象轨迹算 actor 的损失、critic 的回报
       ↓
④ 只更新 actor/critic（不动世界模型）
       ↓
⑤ 收集新真实数据 → 回到 ①
```

四个关键设计（每一个都能对应到本书前面章节的结论）：

| 设计 | 原因 | 对应章节 |
|---|---|---|
| 想象长度 H 很短（15-50 步） | 超过 H 想象不可信 | ch5、ch7、ch16 |
| 价值函数学习用 λ-return（可跨出想象段） | 想象太短但需要远视 | ch16 |
| latent 是随机变量（离散组合） | 未来是多模态的 | ch10 |
| actor 在 latent 上训、在真实上测 | 避免真机试错 | ch9 |

特别是第二条，很值得学：**想象只做 15 步，但价值函数把它"续"到未来**。
这就是 ch16 会说的"用价值函数替代长视界规划"。

## 15.3 损失函数怎么配

一个完整的 latent 世界模型典型有四个损失：

$$
\mathcal{L} = \underbrace{\| \hat o_t - o_t \|^2}_{\text{重构}}
+ \underbrace{\text{KL}\big(q(z_t|h_t,o_t) \,\|\, p(z_t|h_t)\big)}_{\text{动力学一致性}}
+ \underbrace{\| \hat r_t - r_t \|^2}_{\text{奖励}}
+ \underbrace{\text{其他（对比、稀疏、物理）}}_{\text{可选}}
$$

各自的坑：

- **重构损失**会鼓励模型记细节（背景、纹理）。对控制没用，还占容量。
  现代做法：降低重构权重，或在特征空间算损失（V-JEPA 干脆不做重构）。
- **KL 项**是 RSSM 的核心，它让"先验预测"和"后验编码"靠近，
  从而让"没有观测时"也能预测。KL 权重太小会退化成自编码器，太大则学不动。
- **奖励损失**如果稀薄（只在成功时给 1），需要额外的辅助任务（如
  Plan2Explore 的探索奖励）。

## 15.4 三个训练稳定性问题

### (1) 表征坍塌（representation collapse）

编码器把所有输入映射到同一个点（损失很小但毫无信息）。
常见于对比学习/无重构的模型。

对策：EMA teacher、stop-gradient、对比负样本、batch 归一化。

### (2) 动力学与表征互相拖累

如果编码器还在剧烈变化，动力学就没法学稳（目标一直在动）。

对策：分阶段训练、给编码器更低的学习率、EMA 目标网络。

### (3) 想象发散

在 latent 里 rollout 久了，$\hat z$ 会漂出训练分布，解码出垃圾
（exp06 的第二行图就是这个）。

对策：latent clamp（exp06 用过，像素改善 10%，任务指标几乎没变）、
rollout 长度限制、在想象里加噪声做正则。

## 15.5 一个最小可用的训练脚本结构

```python
for iteration in range(N_ITER):
    # ---- 1. 收集真实数据（少量）
    data += collect(env, policy, n_steps=1000)

    # ---- 2. 训世界模型（多轮）
    for epoch in range(E):
        for batch in data:
            loss = recon + kl + reward
            update(model, loss)

    # ---- 3. 在想象里训策略
    for epoch in range(E2):
        start = sample_real_state(data)
        imag = model.imagine(start, policy, horizon=H)
        actor_loss, critic_loss = compute_returns(imag)
        update(actor, actor_loss); update(critic, critic_loss)

    # ---- 4. 周期性在真实环境评估
    if iteration % 10 == 0:
        score = evaluate(env, policy)
        log(score)
```

三个必须的工程细节：

1. **数据缓冲区要保留多样性**（不要只留最新的，否则灾难遗忘）
2. **评估在真实环境做**（latent 里的回报会骗你，ch9 教训）
3. **保留"什么都没学"和"随机策略"两个基线**（否则你不知道自己在进步吗）

## 15.6 计算预算怎么分

大多数人把 90% 的算力花在模型上。经验分配（对机器人任务）：

| 环节 | 占比 | 备注 |
|---|---|---|
| 数据采集（真实或高保真仿真） | 30% | 常被低估 |
| 世界模型训练 | 25% | |
| 策略/规划优化 | 30% | 想象里的 rollout 很贵 |
| 评估与调试 | 15% | 一定要留出来 |

## 15.7 什么时候别做端到端

一个实用判断：**如果你能用 30 行代码写出白盒模型，就别训网络**
（ch13 的 `AnalyticCartPole` 就是例子）。

端到端值得做的情况：

- 有大量数据（>1e5 样本或 >100 小时视频）
- 系统复杂到无法建模（软体、人、流体、接触密集）
- 需要跨任务泛化（一个模型服务多个任务）
- 有明确的"模型不准"的痛点（当前白盒模型在特定工况崩）
