# 第 16 章　失败模式与工程配平

## 16.1 这本书里出现过的所有失败

把前面实验里"翻车"的案例收集起来，它们是最有价值的经验：

| 现象 | 实验 | 根因 | 对策 |
|---|---|---|---|
| 单步 0.003，100 步 4.58（窄覆盖） | exp03 | 分布偏移，网络外推失控 | 输入噪声 0.005 |
| 外推误差 36 倍 | exp04 | 数据没覆盖 | 探索、安全阀 |
| MPC 用错模型比随机更糟 | exp05 | 自信的错误模型 | 视界限制、集成悲观 |
| 在想象里选出"最烂策略" | exp08 | 优化器钻模型漏洞 | 不确定性惩罚、Dyna |
| 像素最好的模型是"什么都不做" | exp06 | 指标错 | 任务相关探针 |
| latent 漂出分布、解码出噪声 | exp06 | 表征外推 | clamp、短视界 |
| 视界一长就崩 | exp10 | 在幻觉里规划 | 视界 = 误差预算 |
| 能量漂移 25% | exp07 | 只学轨迹不学物理 | 结构化先验 |

下面挑三个最容易致命的展开。

## 16.2 失败一：视界选错（最常见）

exp10 的实测（cartpole 平衡，每 4 步重规划）：

| 规划视界 H | 完美模型 | 学到的 MLP |
|---|---|---|
| 5 (0.05 s) | 倒了（201.6） | 倒了（2278） |
| 10 (0.10 s) | **立住（182）** | 倒了（1572） |
| 20 (0.20 s) | 立住（179） | 倒了（2848） |
| 40 (0.40 s) | 立住（134） | 倒了（2692） |
| 80 (0.80 s) | **立住（121，最优）** | 倒了（2441） |

两条完全相反的规律：

- **完美模型：视界越长越好**（单调下降，H=80 代价最低）。
  想得远就能提前减速、提前回正。
- **学到的模型：全都失败**，而且 H=20 时最差（2848）。

为什么 H=20 最差而 H=5/10 略好？因为：

- H 太小 → 近视，看不见"必须往回拉"的必要性（这是完美模型 H=5 也倒的原因）
- H 适当 → 看得到，但看到的是幻觉
- H 太大 → 幻觉累积，规划器在"错误的世界"里找最优，代价函数完全失真

**这个 MLP 的开环误差预算**（exp10 里量到）：
H=5 时 0.047、H=10 时 0.104、H=20 时 0.230、H=40 时 0.398。

所以"误差 < 0.1σ"的步数就是 10 步左右——正好是它"最不差"的那个 H。

> **工程法则**：
> 规划视界 H = 模型开环误差首次超过 0.1σ 的步数，再乘 0.8 保守一点。

## 16.3 失败二：优化器钻模型漏洞

exp08 的读数：在学到的模型里做 CEM 参数优化，想象代价很低，
真实代价 46.6（对照组 0.021，差 2200 倍）。

机理：CEM 的工作就是"找到让代价最小的参数"。如果模型在某个参数区域
输出"完美结果"（幻觉），CEM 一定会找到那里。**优化压力越大，越容易
掉进去。**

四种对策，从便宜到贵：

| 对策 | 做法 | 代价 |
|---|---|---|
| 悲观评估 | 用 K 个模型里最差的回报 | K 倍推理 |
| 不确定性惩罚 | `cost += β · σ(s,a)` | 小 |
| 早停想象 | 想象 H 步就返回（不追求长视界） | 需价值函数 |
| 真实数据回流 | 每轮用真机验一次，失败样本入库重训 | 真机成本 |

MOPO 用第一种，Dreamer 用第二种 + 第三种，Dyna 用第四种。
实际系统基本都会上"第二种 + 第四种"。

## 16.4 失败三：指标自欺

exp06 的排名颠倒（freeze 在像素上最好、在角度上最差）说明：
**只要指标选错，你能让任何模型"看起来很好"。**

最常见的三种自欺：

1. **只报单步 RMSE**（exp03 的 mlp-plain 会是冠军）
2. **像素/重建误差**（freeze 是冠军）
3. **在训练分布内评估**（exp04 的同分布误差 0.009，外推 0.47）

自检清单：

- [ ] 报了开环误差曲线吗？
- [ ] 有一个"什么都不预测"的基线吗？
- [ ] 有分布外测试吗？
- [ ] 有闭环/下游任务指标吗？

## 16.5 配平表：五个维度的权衡

世界模型工程的本质是在五个维度上配平：

| 维度 | 往左调 | 往右调 | 建议 |
|---|---|---|---|
| 精度 | 小模型、快 | 大模型、准但慢 | 先满足闭环频率 |
| 视界 | 短、可靠 | 长、幻觉 | 用误差预算定 |
| 速度 | 线性/小 MLP | 深网络/Transformer | 100 Hz 控制 → <10 ms |
| 泛化 | 专一系统 | 多任务 | 先专用 |
| 可解释 | 黑箱 | 白盒/结构化 | 安全关键必须白盒或加探针 |

一个具体的配平例子（100 Hz 腿部控制）：

- 需要：单步推理 < 5 ms、视界 0.3 s（30 步）、误差 < 0.05σ
- 可行方案：4 层 MLP（宽 256）或线性 + 二次特征
- 不可行：Transformer（延迟超标）、像素级生成（维度太高）

## 16.6 部署前的七个检查

1. **时间尺度一致**：训练 dt = 部署 dt？（exp05 的 wrong-model 就是这里翻车）
2. **标准化器保存了吗**？（`save_mlp` 存了三个统计量）
3. **动作限幅一致吗**？（训练用 ±30，部署用 ±12 会完全不同）
4. **状态定义一致吗**？（角度是 wrap 的还是累积的？四元数顺序？）
5. **推理延迟测量过吗**？（含预处理、含内存分配）
6. **有 fallback 吗**？（模型输出越界时退回 PD/停机）
7. **有在线监控吗**？（残差、σ、输入分布漂移）

第 7 条最容易被忽略。世界模型上线后最危险的情况是"环境变了但模型不知道"，
监控"预测残差"是最便宜的告警信号。

## 16.7 一个真实的调试顺序

当你发现"闭环不行"，按这个顺序查（每一步都能独立验证）：

```
1. 白盒模型能完成吗？        → 不能：任务/代价函数有问题
2. 白盒模型 + 同一规划器能完成吗？ → 不能：规划器有问题
3. 学到的模型，开环误差 < 0.1σ 的步数是多少？
                             → 少于视界：缩短视界或改进模型
4. 视界设成那个步数，能完成吗？ → 不能：模型误差结构有问题（非均匀）
5. 加上不确定性惩罚/悲观评估，能完成吗？
                             → 能：优化器在钻漏洞
6. 都试过还不行                → 数据覆盖不够，回到 ch14
```

这个顺序的价值：**每一步只改一个变量**，避免"乱调参"。

## 16.8 练习

1. 用 exp10 的代码，把 mlp 的规划视界设成 10（误差预算），
   看它是否从"倒了"变成"立住"。如果还是不行，查 §16.7 的第 4 步。
2. 给 exp05 的 CEM 加不确定性惩罚（用 3 模型集成），重跑。
   量出"真实代价"的变化。
3. 故意制造"时间尺度不一致"（训练 dt=0.02，部署 dt=0.01），
   观察所有指标如何变化。这应该成为你的回归测试。
