# 第 14 章　数据：世界模型的真正瓶颈

## 14.1 一个不舒服的事实

大部分世界模型论文的瓶颈不是模型结构，而是**数据覆盖**。

回想 exp04 的数字：

```
训练样本（|θ|≤0.25）: 5711 / 30000

in-dist      linear=0.0014  mlp-ens=0.0090
out-of-dist  linear=1.0014  mlp-ens=0.3273
```

同一个模型，同分布误差 0.009，外推误差 0.33——**差 36 倍**。
训练数据里没有大角度样本，模型就永远学不会大角度。

这不是"数据不够多"，是"数据不够对"。本章讲怎么让数据"对"。

## 14.2 数据的三维：量、覆盖、质量

| 维度 | 含义 | 不足的后果 | 怎么改 |
|---|---|---|---|
| **量** | 样本总数 | 欠拟合、方差大 | 多采 |
| **覆盖** | 状态-动作空间的分布 | 外推崩（exp04） | 探索策略 |
| **质量** | 标签准确性、时间对齐 | 系统性偏差 | 修传感器/同步 |

初学者只关注"量"，实际上**覆盖**才是最致命的。原因很简单：
模型在没覆盖的地方会自信地胡说，而规划器/策略优化专门往那里钻（ch9）。

## 14.3 探索：怎么采到"有用的怪数据"

随机策略是基线，但它在高维系统里极低效。常见策略（按复杂度）：

### (1) 随机动作 + 随机初值

```python
s0 ~ U(范围)                     # 初值要铺满
a  ~ U(-u_max, u_max)            # 动作要大
```
本书 `wm_lib.collect` 就是这个。对 4 维 cartpole 够用。

### (2) 加噪声的 PD 控制器

纯随机会让系统快速发散到边界（撞墙、翻倒），采到的多是"极限状态"。
用"一个粗糙的 PD + 噪声"能让系统停留在**任务相关的区域**：

```python
a = pd(s) + noise
```

这是机器人上最常用的做法（"在正常操作附近扰动"）。

### (3) 基于不确定性的主动采样

用当前模型的集成 $\sigma$ 当探索奖励：

```python
a = argmax_a  sigma(s, a)
```

即"去我最不确定的地方"。这在 MBRL 里很常见（MOPO、Plan2Explore），
效果好但每步都要解一个优化。

### (4) 从失败中采

如果系统有"任务成功/失败"的判定，**失败样本往往信息量最大**。
exp09 里"噪声+延迟"那一组说明：现实系统的误差地板很高，其中一部分
就是"边界情况"没采到。

## 14.4 采样量的经验法则

对低维系统（<10 维状态），本书的经验：

| 目标 | 样本量 | 说明 |
|---|---|---|
| 能跑通流程 | 1e3 | 只看代码正确性 |
| 单步可用 | 1e4 | 线性/MLP 都行 |
| 开环 0.2 s 可用 | 3e4 - 1e5 | 需要覆盖 |
| 闭环 MPC 可用 | 1e5 + 覆盖 | exp05/exp10 用了 2.4e4 但闭环失败 |

对高维（视觉、多物体），量级要再乘 100-1000。

exp03 的"数据量 vs 精度"表说明了另一个道理：

| 训练样本 | linear（50 步开环） | mlp-robust |
|---|---|---|
| 1275 | 0.869 | 1.904 |
| 5100 | 0.809 | **0.590** |
| 25500 | 0.804 | 0.785 |

- 线性模型 800 样本就饱和了（缺表达能力，不是缺数据）
- MLP 在 5000 附近最优（再多需要调超参才能继续受益）
**所以"数据 vs 模型"要一起看：数据不足时用简单模型，数据充足时才上大模型。**

## 14.5 时间对齐：一个隐形杀手

世界模型的数据是 $(s_t, a_t, s_{t+1})$，**三者必须严格对齐同一个时刻**。
真实系统里这里有三个坑：

1. **动作延迟**：你发的 $a_t$ 在 $t+\delta$ 才生效。$\delta$ 常常是
   2-10 个控制周期。
2. **传感器延迟**：读到的 $s_t$ 其实是 $t-\delta'$ 的状态。
3. **时钟不同步**：相机 30 Hz、编码器 1 kHz、IMU 200 Hz，需要插值对齐。

后果：模型会学到"动作的效果比实际晚/早"，从而系统性地错。诊断方法：

> 训练两个模型，一个用 $(s_t,a_t)\to s_{t+1}$，一个用
> $(s_t,a_{t-k})\to s_{t+1}$。如果后者更好，说明你的系统有 $k$ 步延迟。

这是我在真实机器人项目里最常见的一类"模型不收敛"根因。

## 14.6 数据增强：廉价的有效手段

| 手段 | 做法 | 适用 |
|---|---|---|
| 输入噪声 | $s \to s + \epsilon$ | 通用（exp03 用它把开环误差降 26 倍） |
| 时间抖动 | 随机挑 $dt$ 的倍数作为步长 | 时间尺度鲁棒 |
| 对称增强 | 左右镜像（$x \to -x$） | 有对称性的系统 |
| 动作平滑 | 用几个动作的插值 | 真实执行器有低通 |
| 轨迹拼接 | 从长轨迹里随机截片段 | 提高窗口多样性 |

**注意**：增强必须保持物理一致性。镜像增强对 cartpole 有效
（左右对称），但对"只有右轮驱动"的系统就是错的。

## 14.7 数据效率的三个杠杆

如果你只有 1 小时的机器人数据，按这个顺序榨：

1. **换更小的模型**（参数少 10 倍，数据需求少 10 倍，精度差不多）
2. **加结构化先验**（ch13：把速度塞进输入、用物理骨架）
3. **加大噪声增强**（免费的数据倍增）

三招都做完还不够，才考虑去采更多数据。

## 14.8 一个具体的采样脚本（可抄）

```python
def collect_smart(world, n_ep=100, steps=200, seed=0):
    model, data = load(world)
    rng = np.random.default_rng(seed)
    S, A, SN = [], [], []
    for ep in range(n_ep):
        # 1) 初值铺满目标区域（不是只在小范围抖动）
        s0 = sample_initial(rng, ep)
        set_state(model, data, s0)
        # 2) 一半 episode 用随机，一半用"PD + 大噪声"
        mode = "random" if ep % 2 == 0 else "pd"
        for t in range(steps):
            a = random_action(rng) if mode == "random" else pd_noise(s, rng)
            s = get_state(model, data)
            sn = step(model, data, a, substeps=SUB)
            S.append(s); A.append(a); SN.append(sn)
            # 3) 离开目标区域就重开（不要浪费在撞墙的样本上）
            if out_of_region(sn):
                break
    return {"s": np.array(S), "a": np.array(A), "s_next": np.array(SN)}
```

三个设计点（对应上文）：初值铺满、两种模式混合、边界截断。
